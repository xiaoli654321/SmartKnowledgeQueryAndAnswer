## 0. 定位：为什么它是"旁路服务"

```
ai-service 每次问答 ──@Async──> POST /metric/sample ──> samples.jsonl
                                                            │
                                       POST /metric/eval-stored（人工/定时触发）
                                                            ▼
                                                     RAGAS 打分
```

它**不注册 Nacos、不建库**，Java 侧直连 HTTP。原因（讲义原话）：

- 评测在热路径之外：用户提问时不会等它打分，是事后/异步；
- 调用方知道它在哪、通常只有一个实例，不需要注册发现和负载均衡。

> 判断标准：**需要被动态发现的在线服务才需要注册中心；离线/批处理/评测类旁路服务直连即可。**

## 1. store.py：为什么用 JSONL 而不是数据库

```python
_lock = threading.RLock()

def append(sample: Sample) -> int:
    with _lock:
        with open(SAMPLE_FILE, "a", encoding="utf-8") as f:
            f.write(json.dumps(sample.model_dump(), ensure_ascii=False) + "\n")
        return count()
```

四个小设计：

| 设计 | 为什么 |
|---|---|
| **追加写（`"a"`）** | 评测样本是"流水"，只增不改；追加写不会因为一次写坏而毁掉历史 |
| **`ensure_ascii=False`** | 否则中文全变成 `\u5e74\u5047`，出问题时打开文件根本看不懂 |
| **`RLock`** | `append` 内部还要调 `count()`，用普通 `Lock` 会自己把自己锁死 |
| **`load` 跳过坏行** | 一条脏数据不该让整批评测失败；`try/except` 里 `continue` |

`count()` 里 `FileNotFoundError → 0` 也是必需的：**首次运行时文件根本不存在**，这是最常走到的分支。

## 2. ragas_runner.py：三个版本坑，每一个都会让你怀疑人生

### 2.1 指标选择

```python
has_gt = all(s.ground_truth for s in samples)
metrics = [faithfulness, answer_relevancy]
if has_gt:
    metrics.append(context_precision)
```

- `faithfulness` 要 answer + contexts
- `answer_relevancy` 要 question + answer
- `context_precision` **必须有参考答案**（`ground_truth`）

线上样本是模型自己答的，没有标准答案，所以只能算前两个。ragas 0.4 又移除了 `context_relevancy`（那个不需要参考答案），所以"无 GT 时评估检索质量"这条路在当前版本是断的——这是版本限制，不是代码问题。

### 2.2 RunConfig：默认 180s 会把最慢的指标挤爆

```python
run_config=RunConfig(timeout=300, max_workers=2)
```

实测对比：

| 配置 | 结果 |
|---|---|
| 默认（无 RunConfig） | 183s，`faithfulness: NaN` |
| `RunConfig(timeout=300)` + `max_retries=0` | 54s，三个指标全有值 |
| `RunConfig(300)` + `max_retries=1` | 42.7s，faithfulness = 1.0（推荐） |

`faithfulness` 的机制是"先生成陈述、再逐条判断"，是所有指标里最慢的。默认每个任务 180s 超时，多指标并发时它必然被挤爆，而 RAGAS 对超时的处理是**返回 NaN 而不是抛异常**。

### 2.3 结果读取：不能用 `dict(result)`

```python
per_sample = result.scores or []          # 每条样本一个 dict
for row in per_sample:
    v = row.get(name)
    if isinstance(v, (int, float)) and not math.isnan(float(v)):
        vals.append(float(v))
scores[name] = round(sum(vals) / len(vals), 4) if vals else None
```

0.4 的 `EvaluationResult` 不是普通 dict，`dict(result)` 会 `KeyError: 0`。

NaN 要显式跳过，并且**没算出来就返回 `None`**，不要假装 0 分——0 分和"没测"是两件完全不同的事，报告里必须能区分。

### 2.4 一个真实的 flaky 案例

第一次跑 `eval-stored`：

```
ERROR ragas.executor - Exception raised in Job[0]: APIConnectionError(Connection error.)
评测完成 samples=1 metrics={'faithfulness': None, ...}
```

不是代码错，是**网络抖动**。而 `max_retries=0` 时一次抖动就等于丢掉一个指标。

所以最终定的是 `max_retries=1`：给抖动一次机会，又不至于把 300s 的超时吃满。

## 3. dataset_gen.py：让 LLM 出题，再容错解析

```python
text = re.sub(r"^```(?:json)?", "", text).strip()
text = re.sub(r"```$", "", text).strip()
start, end = text.find("["), text.rfind("]")
data = json.loads(text[start:end + 1])
```

模型输出 JSON 的三种典型"脏"：

| 脏法 | 处理 |
|---|---|
| ` ```json ... ``` ` 包一层 | `re.sub` 去掉首尾围栏 |
| 前面来一句"好的，以下是问答对：" | 截取第一个 `[` 到最后一个 `]` |
| 数组里混进非 dict | `isinstance(x, dict) and "question" in x` 过滤 |

不做这些，`json.loads` 十次有三次失败——而失败时最糟的做法是"整批放弃"，所以这里逐篇 try/except，坏一篇跳过一篇。

## 4. main.py：接口就这么几个

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/metric/health` | 存活 + 已攒样本数 |
| POST | `/metric/sample` | 收一条（ai-service 调用） |
| POST | `/metric/samples` | 批量收 |
| POST | `/metric/eval` | 对传入样本评测（可带参考答案 → 三指标） |
| POST | `/metric/eval-stored` | 对已攒样本批量评测（无参考答案 → 两指标） |
| POST | `/metric/dataset` | 从文档自动出题 |
| DELETE | `/metric/samples` | 清空 |

两个细节：

```python
if not req.samples:
    raise HTTPException(status_code=400, detail="samples 不能为空")
```

空列表跑进 RAGAS 会得到一个莫名其妙的内部错误；在入口挡掉，报错信息才对用户有用。

```python
return EvalResponse(metrics=scores, count=len(req.samples), used_ground_truth=has_gt)
```

`used_ground_truth` 这个字段是给调用方看的：**同一份报告，两指标和三指标不能混着比较**。

## 6. 踩坑清单（M4 相关）

| 现象 | 根因 | 处理 |
|---|---|---|
| `ImportError: cannot import name 'context_relevancy'` | ragas 0.4 移除了它 | 无参考答案时只算 faithfulness / answer_relevancy |
| 某指标返回 `NaN` | 默认 180s 超时 + 并发挤爆 | `RunConfig(timeout=300, max_workers=2)` |
| `KeyError: 0` | 用 `dict(result)` 读 0.4 的结果 | 用 `result.scores`（列表，每条一个 dict） |
| 指标时好时坏、日志里 `APIConnectionError` | 网络抖动 + `max_retries=0` | 设 `max_retries=1` |
| `ImportError: No module named pip`（venv） | 之前用 uv 建的 venv 没有 pip | 统一用 conda `py313`，不建 venv |
| 中文在 VS Code 里没提示 | 解释器默认指向系统 Python | `.vscode/settings.json` 指 py313 + `analysis.extraPaths` |
