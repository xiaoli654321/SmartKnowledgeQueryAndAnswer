## 一、M5：网关 RBAC

### 1.1 一个必须讲清的概念：**权限看语义，不看 HTTP 方法**

```java
private static final Set<String> READ_ONLY_POST = Set.of("/ai/ask", "/search/hybrid");
```

`/ai/ask` 是 POST，但它**不改变任何数据**。用 POST 只是因为 query 太长、塞不进 URL。

如果按"POST = 写"一刀切，`guest` 连问问题都会被 403 —— 前台直接不能用。

所以放行判断是：

```java
boolean isRead = "GET".equals(method) || "HEAD".equals(method) || "OPTIONS".equals(method);
boolean isReadOnlyPost = "POST".equals(method) && READ_ONLY_POST.contains(path);
if (isRead || isReadOnlyPost) {
    return chain.filter(exchange);
}
```

> 这类"方法语义 vs 业务语义"的错位，是网关鉴权最常见的坑。

### 1.2 WebFlux 的两个硬性要求

| 要求 | 原因 |
|---|---|
| 不能用 `HttpServletResponse` | 网关是响应式的，返回 403 要自己往 `ServerHttpResponse` 写 body |
| `/actuator/**` 必须放行 | 否则 Prometheus 抓指标被 403 挡掉，现象是 "Grafana 面板全空"，很容易查错方向 |

### 1.3 验证

| 请求 | 结果 |
|---|---|
| `guest` POST `/ai/ask` | ✅ 200（读语义，放行） |
| `guest` POST `/doc/upload` | ✅ 403 |
| `admin` POST `/doc/upload` | ✅ 200 |
| `guest` GET `/doc/13` | ✅ 200 |

## 二、M6：可观测性

### 2.1 三层各管什么

| 层 | 工具 | 回答的问题 |

| 追踪 | SkyWalking | 这一次请求慢在哪一跳？ |

### 2.2 接入方式：零代码侵入

4 个 Java 服务启动时挂 agent：

```powershell
java -javaagent:D:\sw-agent\skywalking-agent.jar `
     -Dskywalking.agent.service_name=ai-service `
     -Dskywalking.collector.backend_service=127.0.0.1:11800 `
     -jar ai-service-0.0.1-SNAPSHOT.jar
```

> ⚠️ agent 路径**不能带空格**。放在 `D:\sw-agent` 而不是项目目录里，就是因为项目路径含 `Smart Knowledge_Q&A`，`-javaagent` 参数会被空格截断，报 `Error opening zip file ... Smart`。

### 2.3 自定义指标（讲义作业）

`FailoverChatService` 里每个供应商单独计时：

```java
Timer.Sample sample = Timer.start(meterRegistry);
try {
    LlmReply reply = p.chat(prompt);
    sample.stop(Timer.builder("llm.call.duration")
            .tag("provider", p.name()).tag("result", "success").register(meterRegistry));
    meterRegistry.counter("llm.call.total", "provider", p.name(), "result", "success").increment();
```

为什么按 `provider` 打标签：只有一个"LLM 总耗时"时，你分不清是**云端变慢**还是**降级到本地**——处置方式完全不同。

暴露出来的指标：

```
llm_call_duration_seconds_count{provider="zai-org/GLM-5.3-Flash",result="success"} 1
llm_call_duration_seconds_sum{...} 3.72
```

## 三、前端：一个 nginx 出两个站点

### 3.1 为什么用 nginx 而不是把页面塞进某个 Java 服务

| 方案 | 问题 |
|---|---|
| 塞进 doc-service 的 static | 页面和业务耦合；网关路由还要为静态资源单开一条 |
| 前端直连 8081/8082/8083 | 跨域（CORS）+ 暴露内部端口，还要在 4 个服务里各配 CORS |
| **nginx 反代（本项目）** | 静态资源与 API **同源**，零跨域；`/api/*` 统一进网关，鉴权只做一次 |

### 3.2 目录

```
web/
├── index.html      前台：问答
├── admin.html      后台：上传 / 版本 / 计量 / 评测
├── assets/
│   ├── style.css   深色主题
│   └── app.js      api() / metric() 两个客户端 + 工具函数
└── nginx.conf
```

### 3.3 反代规则

```nginx
location /api/ {                      # /api/doc/upload -> gateway/doc/upload
    proxy_pass http://host.docker.internal:8080/;
    proxy_set_header X-User-Role $http_x_user_role;   # 角色透传
    proxy_read_timeout 180s;                          # 问答要等大模型
    client_max_body_size 40m;
}

location /metric/ {                   # 评测是旁路服务，不进网关
    proxy_pass http://host.docker.internal:8090/metric/;
    proxy_read_timeout 300s;                          # RAGAS 要几十秒到几分钟
}
```

`host.docker.internal` 是 Docker Desktop 提供的"容器访问宿主机"域名。

### 3.4 前台（`/`）

- 输入问题 + 租户 ID → `POST /api/ai/ask`
- 展示：答案、供应商、耗时、Token、出处条数
- 出处可点开看检索到的原文片段（对应答案里的 `[1][2]`）
- 角色下拉：`guest` 也能提问（因为 `/ai/ask` 在只读白名单里）

### 3.5 后台（`/admin.html`）

| 区块 | 操作 | 走的接口 |

| 身份 | 选 admin / editor / guest | 请求头 `X-User-Role` |
| 上传文档 | 选文件 + 标题 → 上传 | `POST /api/doc/upload` |
| 文档与版本 | 查文档 / 查版本 / 回滚 | `/api/doc/{id}`、`/versions`、`/rollback` |
| 运营数据 | 查 Token / 服务健康 / 跑评测 | `/api/ai/token/tenant/{id}`、`/api/actuator/health`、`POST /metric/eval-stored` |

## 五、踩坑清单（M5/M6/前端）

| 现象 | 根因 | 处理 |
|---|---|---|
| 前台提问返回 403 | 网关把 POST 一律当写操作 | 加只读 POST 白名单 `/ai/ask`、`/search/hybrid` |
| Grafana 面板全空 | 网关把 `/actuator/**` 也拦了 | 放行 actuator |
| `-javaagent` 报 `Error opening zip file ... Smart` | 项目路径含空格，参数被截断 | agent 放无空格路径（`D:\sw-agent`） |
| 4 个服务同时启动，部分注册失败 | Nacos gRPC 未就绪/并发注册超时 | 等 readiness 返回 OK，逐个启动 |
| jar 打包失败 `Unable to rename ... .original` | 旧 jar 正被运行中的进程占用 | 先停进程，再 `mvn clean package` |
| 前端跨域 | 前端直连 8080/8081 | 统一走 nginx 同源反代 |
| 评测返回 502 | nginx 反代 8090 但 metric-service 没起 | 先起 Python 服务 |

### 4.2 消息渲染的三个细节

**① 出处做成 chip，点开看原文**

```html
<span class="source-chip" data-msg="1" data-ci="0">[1] 文档 13 · 片段 0</span>
<div class="source-body" id="src-1-0">员工累计工作满一年……</div>
```

chip 默认收起，点击 `toggle('open')` 展开片段原文 —— 对应答案里的 `[1]`。

**② 极简 markdown**

模型返回的是 markdown，直接当纯文本显示会出现 `**5 天**` 这种星号。前端只处理三种最常见语法：

```js
function md(s){
  let h = esc(s);                                   // 先转义，防 XSS
  h = h.replace(/\*\*([^*]+)\*\*/g, '<b>$1</b>');   // 粗体
  h = h.replace(/`([^`]+)`/g, '<code…>$1</code>');   // 行内代码
  h = h.replace(/^\s*[-*]\s+/gm, '• ');             // 列表项
  return h;
}
```

顺序很重要：**先转义再替换**，否则模型输出的 `<script>` 会被当成标签执行。

**③ 打字指示**

请求发出后先在对话流里插一行 `● ● ● 正在检索并组织答案…`，拿到响应再替换成正式消息 —— 否则用户会以为卡住了（首次回答通常 5~15 秒）。

### 4.3 登录态

- 顶栏右侧是「登录 / 身份徽章 + 退出」，不再是角色下拉框；
- `api()` 自动带 `Authorization: Bearer <token>`；**收到 401 自动清会话并弹登录框**；
- 后台与前台共用同一个登录弹窗（`app.js` 注入）。

### 4.7 主题：浅色 / 深色可切换

顶栏右侧多了一个 ☾ / ☀ 按钮，一键切换，选择记在 `localStorage`。

**实现方式：CSS 变量 + `data-theme`**

```css
:root{ --bg:#fff; --side:#f7f7f8; --text:#1f2328; --accent:#4d6bfe; ... }
html[data-theme="dark"]{ --bg:#14161a; --side:#0f1115; --text:#e6e8ec; --accent:#7b95ff; ... }
```

所有颜色都走变量（`background:var(--card)`），所以切主题只是换一组令牌，**不用写第二套样式**。

三个细节：

| 细节 | 做法 |
|---|---|
| 首次访问跟随系统 | `matchMedia('(prefers-color-scheme: dark)')`，用户手动切过之后以手动为准 |
| 刷新不闪白 | 在 `<script>` 里**解析时立即**给 `<html>` 设 `data-theme`，早于首帧绘制 |
| 演示/分享链接 | `?theme=dark` 或 `?theme=light` 强制指定（截图、录屏用） |

深色下注意的对比度：主色从 `#4d6bfe` 提到 `#7b95ff`（深底上更亮），正文 `#e6e8ec`，次要文字 `#8b93a1`，卡片 `#1a1d23` 与背景 `#14161a` 分两层——纯黑底配纯白字看久了会累。

实测：前台对话页与后台概览页在两种主题下都正常，切换后刷新仍保持。
